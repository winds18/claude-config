# 界面与交互质量

界面是给人用的。判断标准只有一个：一位认真的设计师和一位第一次使用的用户，会不会觉得这是人做的、顺手的东西。

工具：`python3 ${CLAUDE_SKILL_DIR}/scripts/ui_lint.py --changed`（或给出文件路径）列出可客观检出的问题；`ui-reviewer` 子代理看真实渲染结果。视觉方向（配色、字体、版式的取舍）建议另装官方 `frontend-design` 插件，本技能不重复它。

## 1. 先定性（动手前，写成几行，不是文档）

- **产品类型**决定密度与表现力：工具/后台要紧凑、安静、可扫读；营销页才需要大标题与视觉冲击；移动端优先单手操作。不要把营销页的写法用在工具里。
- **已有设计系统优先**：先读项目的 token、组件库和相邻页面，沿用它的间距、字号、圆角、颜色与交互方式。没有才新定，且只定一套。
- **主任务**：这个界面上用户最常做的一件事是什么，它必须最显眼、步骤最少。
- **状态表**：列出本界面的每个状态并逐个实现——默认、加载、空、出错、部分成功、禁用、成功、内容超长、窄屏。漏掉状态是"不像人做的"最常见原因。

## 2. 视觉底线

- 间距用一套倍数（4 或 8），字号不超过 5–6 级，圆角与阴影各一套；层级靠间距、字重和对比建立，而不是靠加框、加色、加阴影。
- 颜色：中性色 + 一个强调色 + 语义色（成功/警告/错误）。正文对比度达到 WCAG AA。强调色只给主操作。
- 对齐到同一条线；同类元素长得一样，不同类的才不一样。
- 用真实内容：真实长度的标题、真实的数据量、最长的那个名字。不用 lorem、不编造漂亮的统计数字。
- 图标用同一套图标集、同一线宽；不用 emoji 当图标。

## 3. "生成味"清单（它们是默认值，不是选择；没有理由就不要用）

- 紫/蓝渐变背景、渐变文字、毛玻璃卡片、到处发光的阴影。
- 内容被切成一排完全相同的圆角卡片（图标 + 标题 + 两行字），所有东西一个圆角、一种阴影。
- 每个标题上方的全大写小标签；标题里单独给一个词上色或倾斜；链接后缀箭头。
- 什么都居中；首屏"大数字 + 小说明"。
- 每个区块淡入上滑、每张卡片悬停放大；与操作无关的动画。
- 文案里的 emoji、感叹号和"轻松""强大""无缝"这类形容词；占位的假人名假公司。
- 为显得丰富而加的装饰：多余的分隔线、徽章、编号（内容不是序列却写 01/02/03）。

## 4. 交互底线

- **每个操作都有回应**：点击后 100ms 内有可见变化；超过 1 秒给进度；完成与失败都要说清楚。按钮文字写它做什么（"保存修改"而不是"提交"），同一动作全程同名。
- **不丢用户的东西**：出错或跳转后保留已填内容；破坏性操作优先可撤销，其次才是确认框，确认框要写明后果。
- **表单**：有可见标签（占位符不是标签）；失焦或提交时校验，不在输入中途报错；错误写在字段旁并说明怎么改；合理的默认值与输入类型。
- **状态不突变**：加载用占位骨架保持布局，不让内容跳动；空状态告诉用户下一步能做什么；错误可重试。
- **键盘与可达性**：全部操作可用键盘完成，焦点可见且顺序合理；可点击的东西用按钮或链接；点击目标不小于 44px；图片有替代文本；尊重"减少动效"。
- **不打断**：弹窗只用于必须当场决定的事；不劫持滚动、不自动播放、不无故弹提示。
- **遵循平台习惯**：Web、macOS、iOS、Android 各有约定（返回、手势、快捷键、菜单位置），不自创。

## 5. 验证（交付前必须做，做不了要明说）

1. `ui_lint.py --changed` 无未解释的提示。
2. **真实渲染**：桌面端用 Browser 预览（`.claude/launch.json`）或模拟器；至少看窄屏（约 375）和宽屏（约 1280），支持时看深色模式。逐个制造状态表里的每个状态并截图看一眼。
3. 只用键盘走一遍主任务。
4. 派 `ui-reviewer` 看渲染结果（给它预览地址、主任务与状态表）；只处理它能指出具体位置和原因的问题。
5. 没有浏览器的环境（如 SSH 会话）：在交付说明里写明"未做真实渲染验证"，不要声称界面已验证。

## 6. 交付说明

附关键状态的截图或说明看了哪些状态；列出有意不做的状态与原因；涉及的设计取舍一句话说明。
