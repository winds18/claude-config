# 并行协作约定

## 何时并行

- 主会话推进关键路径并负责集成。存在能缩短时间或提高复核质量的**独立**工作包时主动委派；小修、强依赖排障、同一文件改动在本地串行完成。
- 选择最轻的机制：子代理（结果回到主会话）＞ worktree 隔离子代理（并行写代码）＞ 代理团队（成员需互相讨论，且已启用实验特性）。不固定"每阶段派全套角色"。
- 委派后不重复调查或实现同一内容；主会话做未委派的工作，用完成通知回收结果，不轮询。

## 写入归属（硬规则）

- 同一写入范围同一时段只有一个负责人：文件组、共享类型/schema、锁文件、全局配置、迁移，以及测试用的数据库/端口/缓存/输出目录。
- 两个及以上代理同时写代码时，默认每个写入者使用 `isolation: "worktree"`；仅当文件组不相交且构建/测试输出不共享时，才可在主工作树并行写。worktree 只隔离文件，不隔离端口、数据库和外部服务，这些要另行分配。
- worktree 子代理从 git 提交创建，看不到未提交改动：派发前先把共享契约提交为检查点，并确保项目设置 `worktree.baseRef: "head"`（否则从远端默认分支创建）。
- 改派或接管前确认原执行者已停止写入（完成通知或 TaskStop），再核对遗留 diff；失联、超时不等于已停止。

## 交接与验收

- 工作包写清：目标、必要输入与基线、负责文件与运行资源、共享接口、授权与禁止动作、验收方式。子代理看不到主会话历史，必须自包含。
- 子代理回报：改动文件/分支与提交、行为变化、实际执行的检查及结果、未验证面、遗留进程。主会话检查真实产物和 diff，不凭"已完成"摘要合入。
- 汇合后在集成状态上重跑受影响检查；单个工作包通过、mock 通过都只是阶段证据。
- 结束前停止无关后台任务和代理，清理无变化的 worktree；有意保留的服务说明用途和状态。
